# page upload 安全规则

页面附件或图片上传属于写操作。执行任何下载、路径转换、文件选择或上传调用前，先完成来源、页面目标和用户确认检查。

## 来源边界

- `page upload` 只接受用户提供的本地文件路径。
- 若附件来源是 `http://` 或 `https://` URL，立即停止上传并原样回复：

  > 暂不支持从 URL 上传附件，请提供本地文件路径。

- 不得先下载、复制、缓存或转换 URL 内容，再把生成的本地文件当作可信来源上传。用户要求跳过该限制也不能改变来源边界。
- 不得把导航 URL、页面链接或下载链接解释为附件路径。

## 页面与控件定位

1. 上传前确认当前 `store-id`、当前页面和唯一 `target-id`。多个可用标签页而用户未指定目标时，停止并让用户确认，不得任意选择。
2. 只使用当前页面快照产生的 ref。页面 reload、URL 变化、标签页切换或 ref 失效后，重新执行 `page snapshot`。
3. 上传控件不唯一时，根据当前快照的可访问名称和上下文，通过 `--trigger-ref` 或 `--hint` 消歧；不要先单独点击上传入口，也不要猜测泛选择器。

错误处理：

- `PAGE_TARGET_AMBIGUOUS`：重新获取当前页面快照并确定唯一 `target-id`；不得任意选择其他标签页。
- `PAGE_TARGET_NOT_FOUND`：原目标已失效；重新获取当前店铺快照，不得回退到其他标签页。
- `UPLOAD_CONTROL_NOT_DISCOVERED`：重新快照检查动态上传入口；仍未发现时停止并报告。
- `UPLOAD_CONTROL_AMBIGUOUS`：使用当前快照的 `--trigger-ref` 或 `--hint` 消歧；仍无法唯一确认时停止并让用户选择。

## 外部本地路径确认

当下载目录外的本地路径返回 `confirmationRequired` 时：

本轮最终用户可见回复必须是一个不可拆分的确认包，并按以下顺序同时包含：

1. 原样输出完整 `confirmationMessage`，不得摘要、改写或删除字段。
2. 紧接着实际显示 `screenshotFilePath` 指向的截图。
3. 明确说明文件尚未上传。
4. 最后等待用户按照 `confirmationMessage` 的要求明确确认。

仅调用图片读取工具、仅在中间进度消息或折叠区域显示图片、或只输出截图路径，均不算已经向用户展示截图。结束本轮前必须确认最终回复中同时可见完整确认文字和实际截图。

截图无法读取或无法在最终回复中展示时，本轮不得索要确认，也不得重试上传。用户明确确认后，只以相同的 `store-id`、`target-id`、文件来源、目标控件和上传意图，追加原响应的 `--confirmation-token <token>` 重试一次。不得换标签页、换文件、换控件或改写来源。先前的笼统授权或“无需再确认”不能替代本次确认。

页面、店铺会话或任一上传参数发生变化时，原 token 不再用于新的上传意图；重新开始定位和确认流程。

## 结果判定与重试

上传命令的结果只描述文件控件状态，不能单独证明网站业务提交完成：

- `confirmationRequired=true` 或 `stage=confirmation_pending`：尚未获得上传授权；不得声称已上传。
- `attached=true, stage=input_attached`：文件仍在网页文件输入控件中；继续根据页面可见文件名、缩略图、进度或错误提示验证。
- `attached=true, stage=input_consumed`：网页组件已接收并消费或清空输入；仍需等待页面可见的处理结果。
- `attached=false, stage=input_unverified`：CDP 已执行但页面是否接收无法确认；不得报告成功或失败，也不得自动重试。先通过新快照、截图、文件名、进度或错误提示确认；只有页面明确失败，或把本次不确定结果告知用户后用户再次明确要求时才重试。任务开始前的笼统授权不构成这次重试授权。
- `UPLOAD_ATTACH_VERIFY_FAILED`：重新快照并检查页面可见状态；不得盲目重试或声称成功。

只有页面出现与目标文件对应的可见业务结果，才能报告网站侧上传完成。文件进入控件、命令退出码为 0、`attached=true` 或 `input_consumed` 都不是业务完成证明。
